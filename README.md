# Verification screen starter

Open `index.html` in a desktop browser. No installation, framework, account or backend is needed. Keep `index.html`, `style.css` and `script.js` together. If local files are restricted, run `python3 -m http.server 8000` from this folder and open `http://localhost:8000/`; stop the server when finished.

This is an incomplete starter, not the final solution. Its submit handler prevents every submission and shows a starter notice. Implement the format check, invalid-input feedback and finished responsive styling yourself using `REQUIREMENTS_AND_TESTS.txt` and `UI_REFERENCE.svg`.

Do not publish real OTPs, credentials, personal contact details or API keys. Use local format-test strings only. No value is an accepted authentication code; valid format is not proof of identity. Client-side validation alone cannot secure a registration portal. Real verification needs a separately implemented server with expiry, attempt limits and replay protection, outside this small UI task.

Final README to submit: replace this starter text with your actual run instructions, validation logic, keyboard/mobile test results, remaining limitations and confirmation that the demo does not authenticate or send codes. Include only claims you tested.

Submit a GitHub repository URL in `PROJECT_LINKS.txt` inside the final Drive folder. The repository must contain the final three code files and README; no repository URL has been created by this pack. No live deployment is required. Repository access must work for the designated reviewer.
